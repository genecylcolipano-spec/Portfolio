# Portfolio V5

A modern personal portfolio website with an integrated admin dashboard, built with React, Vite, Tailwind CSS, and Supabase.

It ships with a public-facing site (hero, about, projects, certificates, real-time comments, contact form) and a protected admin dashboard for full CRUD on your content.

---

## Tech Stack

- **ReactJS** — frontend framework (React 18 + Vite 8, Rolldown bundler)
- **Tailwind CSS** — utility-first CSS framework
- **Supabase** — Postgres database, auth, storage, and realtime
- **React Router v7** — client-side routing with dynamic project slugs
- **AOS** — animate-on-scroll
- **Framer Motion** — welcome screen transitions
- **Material UI** — tabs and certificate lightbox
- **Lucide** — icon library
- **SweetAlert2** — alert dialogs
- **react-helmet-async** — per-page SEO meta tags

---

## User Roles

| Role | Access |
|---|---|
| **Visitor (Public)** | View projects, certificates, and comments — leave a comment |
| **Admin** | Log in to the dashboard — full CRUD on projects & certificates — delete and pin/unpin comments |

## Getting Started

### Prerequisites

- Node.js `>= 20.19` (required by Vite 8)
- npm

### 1. Install

```bash
npm install --legacy-peer-deps
```

> `--legacy-peer-deps` is required because `react-swipeable-views` has not
> updated its React 18 peer range.

### 2. Environment Variables

Vite loads env files per mode, highest priority first. `npm run dev` runs in
mode `development`; `npm run build` runs in mode `production`.

| File | Applies to |
|---|---|
| `.env.[mode].local` | that mode only |
| `.env.[mode]` | that mode only |
| `.env.local` | all modes |
| `.env` | all modes |

For local development, copy the template:

```bash
cp .env.example .env.development.local
```

```env
VITE_SUPABASE_URL=https://your-project-ref.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
VITE_CONTACT_EMAIL=you@example.com
```

- Find the Supabase values under **Project Settings → API**.
- `VITE_CONTACT_EMAIL` is the address the contact form relays to via [FormSubmit](https://formsubmit.co). You must confirm the address once, on your first submission.
- Every `.env*` file except `.env.example` is gitignored — never commit real credentials.

There is deliberately no `.env`, because a file that applies to *all* modes is
how live credentials end up loaded into local development by accident. Point
`npm run dev` at a separate project — see
[Local Development vs. Production](#local-development-vs-production).

### 3. Database Setup

Open your Supabase project → **SQL Editor** → run the script below.

It is safe to re-run: tables use `IF NOT EXISTS`, policies are dropped before
being recreated, and the realtime step ignores an already-registered table. So
if a statement fails partway through, you can fix it and run the whole thing
again without cleaning up by hand.

```sql
-- ============================
-- TABLES
-- ============================
CREATE TABLE IF NOT EXISTS public.projects (
  id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  "Title" text,
  "Description" text,
  "Img" text,
  "Link" text,
  "Github" text,
  "Features" jsonb,
  "TechStack" jsonb,
  is_published boolean DEFAULT true,
  order_index int DEFAULT 0,
  created_at timestamptz DEFAULT now()
);

CREATE TABLE IF NOT EXISTS public.certificates (
  id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  "Img" text,
  created_at timestamptz DEFAULT now()
);

CREATE TABLE IF NOT EXISTS public.portfolio_comments (
  id uuid DEFAULT gen_random_uuid() PRIMARY KEY,
  content text NOT NULL,
  user_name text NOT NULL,
  profile_image text,
  is_pinned boolean DEFAULT false,
  created_at timestamptz DEFAULT now()
);

CREATE TABLE IF NOT EXISTS public.profiles (
  id uuid PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  username text UNIQUE NOT NULL,
  role text NOT NULL CHECK (role IN ('admin', 'user')),
  created_at timestamptz DEFAULT now()
);

-- ============================
-- ROW LEVEL SECURITY
-- ============================
ALTER TABLE public.projects ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.certificates ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.portfolio_comments ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY;

-- Authenticated users may only read their own profile.
-- The login flow relies on this to check the user's role.
DROP POLICY IF EXISTS "user can read own profile" ON public.profiles;
CREATE POLICY "user can read own profile"
ON public.profiles FOR SELECT
TO authenticated
USING ((SELECT auth.uid()) = id);

DROP POLICY IF EXISTS "public read projects" ON public.projects;
CREATE POLICY "public read projects"
ON public.projects FOR SELECT USING (true);

DROP POLICY IF EXISTS "public read certificates" ON public.certificates;
CREATE POLICY "public read certificates"
ON public.certificates FOR SELECT USING (true);

DROP POLICY IF EXISTS "public read comments" ON public.portfolio_comments;
CREATE POLICY "public read comments"
ON public.portfolio_comments FOR SELECT USING (true);

-- Visitors may post comments, but may never self-pin.
DROP POLICY IF EXISTS "public insert comment" ON public.portfolio_comments;
CREATE POLICY "public insert comment"
ON public.portfolio_comments FOR INSERT
WITH CHECK (is_pinned = false);

DROP POLICY IF EXISTS "admin manage projects" ON public.projects;
CREATE POLICY "admin manage projects"
ON public.projects FOR ALL
USING (
  EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
);

DROP POLICY IF EXISTS "admin manage certificates" ON public.certificates;
CREATE POLICY "admin manage certificates"
ON public.certificates FOR ALL
USING (
  EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
);

DROP POLICY IF EXISTS "admin manage comments" ON public.portfolio_comments;
CREATE POLICY "admin manage comments"
ON public.portfolio_comments FOR ALL
TO authenticated
USING (
  EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
)
WITH CHECK (
  EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
);

-- ============================
-- STORAGE
-- ============================
INSERT INTO storage.buckets (id, name, public)
VALUES ('project-images', 'project-images', true)
ON CONFLICT DO NOTHING;

DROP POLICY IF EXISTS "admin upload project images" ON storage.objects;
CREATE POLICY "admin upload project images"
ON storage.objects FOR INSERT
WITH CHECK (
  bucket_id = 'project-images'
  AND EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
);

DROP POLICY IF EXISTS "public read project images" ON storage.objects;
CREATE POLICY "public read project images"
ON storage.objects FOR SELECT
USING (bucket_id = 'project-images');

INSERT INTO storage.buckets (id, name, public)
VALUES ('certificate-images', 'certificate-images', true)
ON CONFLICT DO NOTHING;

DROP POLICY IF EXISTS "admin upload certificate images" ON storage.objects;
CREATE POLICY "admin upload certificate images"
ON storage.objects FOR INSERT
WITH CHECK (
  bucket_id = 'certificate-images'
  AND EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
);

DROP POLICY IF EXISTS "public read certificate images" ON storage.objects;
CREATE POLICY "public read certificate images"
ON storage.objects FOR SELECT
USING (bucket_id = 'certificate-images');

INSERT INTO storage.buckets (id, name, public)
VALUES ('profile-images', 'profile-images', true)
ON CONFLICT DO NOTHING;

DROP POLICY IF EXISTS "public upload profile images" ON storage.objects;
CREATE POLICY "public upload profile images"
ON storage.objects FOR INSERT
TO public
WITH CHECK (bucket_id = 'profile-images');

DROP POLICY IF EXISTS "public read profile images" ON storage.objects;
CREATE POLICY "public read profile images"
ON storage.objects FOR SELECT
TO public
USING (bucket_id = 'profile-images');

INSERT INTO storage.buckets (id, name, public)
VALUES ('resumes', 'resumes', true)
ON CONFLICT DO NOTHING;

DROP POLICY IF EXISTS "admin upload resumes" ON storage.objects;
CREATE POLICY "admin upload resumes"
ON storage.objects FOR INSERT
WITH CHECK (
  bucket_id = 'resumes'
  AND EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
);

DROP POLICY IF EXISTS "public read resumes" ON storage.objects;
CREATE POLICY "public read resumes"
ON storage.objects FOR SELECT
USING (bucket_id = 'resumes');

-- ============================
-- SITE CONFIG (settings panel)
-- ============================
CREATE TABLE IF NOT EXISTS public.site_config (
  key   text PRIMARY KEY,
  value text NOT NULL DEFAULT ''
);

ALTER TABLE public.site_config ENABLE ROW LEVEL SECURITY;

GRANT SELECT, INSERT, UPDATE, DELETE ON public.site_config TO authenticated;
GRANT SELECT ON public.site_config TO anon;

DROP POLICY IF EXISTS "public read site_config" ON public.site_config;
CREATE POLICY "public read site_config"
ON public.site_config FOR SELECT USING (true);

DROP POLICY IF EXISTS "admin manage site_config" ON public.site_config;
CREATE POLICY "admin manage site_config"
ON public.site_config FOR ALL
TO authenticated
USING (
  EXISTS (SELECT 1 FROM public.profiles WHERE id = auth.uid() AND role = 'admin')
)
WITH CHECK (
  EXISTS (SELECT 1 FROM public.profiles WHERE id = auth.uid() AND role = 'admin')
);

-- Seed default (empty) values — safe to re-run.
-- Wrapped in a transaction that disables row-security for this statement
-- so it works regardless of which role the SQL Editor uses.
BEGIN;
SET LOCAL row_security = off;
INSERT INTO public.site_config (key, value) VALUES
  ('display_name',     'Genecyl'),
  ('job_title',        'Frontend Developer'),
  ('status_badge',     'Ready to Innovate'),
  ('tagline',          'Building websites that are innovative, functional, and user-friendly digital solutions.'),
  ('typewriter_words', 'Front-End Developer, Tech Enthusiast'),
  ('tech_stack',            'React, Javascript, Node.js, Tailwind'),
  ('portfolio_tech_stack',  'React, Javascript, Node.js, Tailwind'),
  ('site_url',         'https://genecyl.com'),
  ('about_subtitle',   'Transforming ideas into digital experiences'),
  ('about_bio',        'I''m an Informatics Engineering student focused on Front-End development. I care about crafting engaging digital experiences and always aim to deliver the best possible solution for every project I take on.'),
  ('about_quote',      'Leveraging AI as a professional tool, not a replacement.'),
  ('github_url',       ''),
  ('linkedin_url',     ''),
  ('instagram_url',    ''),
  ('youtube_url',      ''),
  ('tiktok_url',       ''),
  ('resume_url',       ''),
  ('resume_filename',  ''),
  ('profile_image_url',''),
  ('contact_email',    ''),
  ('career_start',     '2021-01-01'),
  ('years_experience', ''),
  ('education',        '[]')
ON CONFLICT (key) DO NOTHING;
COMMIT;

-- ============================
-- REALTIME (live comments)
-- ============================
-- Adding a table that is already in the publication raises an error,
-- so swallow that one case to keep the script re-runnable.
DO $$
BEGIN
  ALTER PUBLICATION supabase_realtime ADD TABLE public.portfolio_comments;
EXCEPTION
  WHEN duplicate_object THEN NULL;
END $$;
```

> You can also enable realtime from the UI: **Table Editor → portfolio_comments → Enable Realtime**.

### 4. Create Your Admin Account

**Step 1** — In the Supabase Dashboard go to **Authentication → Users → Add User**, create the user, then copy the generated User ID (UUID).

**Step 2** — Run this in the SQL Editor, replacing `USER_UUID`:

```sql
INSERT INTO public.profiles (id, username, role)
VALUES ('USER_UUID', 'genecyl', 'admin');
```

Only accounts with `role = 'admin'` can reach `/dashboard`; everyone else is redirected to `/login`.

## Local Development vs. Production

The admin dashboard deletes rows immediately — `window.confirm` is the only
guard, and there is no undo or soft-delete anywhere in the schema. Local
development should therefore never be able to reach live data.

Use two Supabase projects. The free tier allows two:

| Environment | Project | Credentials live in |
|---|---|---|
| Local (`npm run dev`) | `portfolio-dev` | `.env.development.local` on your machine |
| Live (deployed) | `portfolio` | Your host's environment variables (e.g. Vercel) |

To set up the dev project, run the [database script](#3-database-setup) in its
SQL Editor and create [an admin user](#4-create-your-admin-account) there too.
It's a fresh database, so the script applies cleanly.

Keep production credentials out of files entirely — set them in the Vercel
dashboard so they never sit on disk and can't leak into a local build.

### Testing a production build locally

Because there is no `.env`, `npm run build` picks up no variables by default, so
the bundle will throw on load when opened via `npm run preview`. That is
intentional. If you need to verify a production build locally, create a
`.env.production.local` (also gitignored) with your **dev** project's values.

### A caveat with two projects

The two databases will drift. Every schema change has to be applied by hand in
both SQL Editors, and nothing enforces that you did. That's fine while the
schema is stable, which for these four tables it likely will be.

If you do start iterating on the schema, move to the Supabase CLI instead:

```bash
npx supabase init
npx supabase link --project-ref <your-project-ref>
npx supabase db pull      # generate a migration from the live schema
npx supabase start        # full local stack in Docker
```

That puts migrations under version control, and `npx supabase db reset`
rebuilds the local database from scratch — which also means the setup script
never has to be safe to re-run.

> Free-tier projects pause after roughly a week of inactivity and need a click
> in the dashboard to resume.

## Pages & Features

### Public

- **Home** — hero with typewriter effect, status badge, tech stack chips, and social links
- **About** — bio, quote, and live counters for projects, certificates, and years of experience
- **Portfolio** — swipeable tabs for Projects, Certificates, and Tech Stack, with "see more" paging
- **Project Detail** (`/project/:slug`) — slug-based route with per-project SEO meta and JSON-LD
- **Contact** — validated form relayed through FormSubmit
- **Comments** — real-time comment wall with optional profile photo upload and a pinned admin comment
- **404** — catch-all not-found page

### Admin (`/dashboard`)

- **Login** — email/password auth via Supabase Auth, gated on the `admin` role
- **Projects** — create, edit, and delete projects; manage image, links, features, and tech stack
- **Certificates** — drag-and-drop upload and delete
- **Comments** — pin/unpin to highlight, delete spam, plus search and pagination

## Deployment

The included `vercel.json` rewrites all routes to `/` so client-side routing works on refresh.

1. Push the repository to your Git host.
2. Import it into Vercel (or any static host).
3. Add `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, and `VITE_CONTACT_EMAIL` as environment variables.
4. Deploy — the build output is `dist/`.

For other hosts, run `npm run build` and serve `dist/` with a catch-all rewrite to `index.html`.

## Optional: Live Presence Widget

`src/components/PresenceWidget.jsx` can display what you're currently listening to, coding, or playing. It stays hidden unless you set:

```env
VITE_PRESENCE_API=https://your-presence-endpoint/api/presence
```

The endpoint should return `{ "activities": [{ "type": "spotify", "title": "...", "artist": "...", "image": "..." }] }`.
